# Публикация на Linux

Сайт обслуживает Nginx из `/var/www/qupersimulator/site/current`.
`current` — ссылка на активный выпуск в `site/releases`. Обновление
переключает ссылку атомарно. Старые выпуски остаются для отката.
Хешированные JS/CSS находятся также в общем каталоге `site/assets`:
открытые до публикации вкладки могут загрузить свои прежние файлы.

## Доступ GitHub Actions

Пользователь `quper-deploy` не имеет sudo и доступа к Docker. Его SSH-ключ
разрешает только команду `publish <40-значный SHA коммита>` через
`/usr/local/bin/quper-site-deploy`. Архив сайта поступает через stdin.
Команды shell, SCP и перенаправление портов этим ключом запрещены.

На GitHub откройте Settings → Secrets and variables → Actions и создайте секрет:

| Секрет            | Содержимое                                                                 |
| ----------------- | -------------------------------------------------------------------------- |
| `SITE_DEPLOY_KEY` | Полный приватный ключ выделенного пользователя, включая строки BEGIN / END |

IP задан в workflow, проверенный публичный ключ сервера — в deploy/ssh_known_hosts.
При замене сервера обновите IP и проверьте новый публичный ключ.

Ключ хранится вне репозитория. Пароль root не используется в Actions.
Не добавляйте файлы ключей или содержимое секретов в Git.

## Проверки

`python3 -m unittest discover -s deploy -p 'test_publish_site.py'`

Проверяются переключение выпусков, сохранение прежних assets, запрет выхода
за каталог архива, отказ при отсутствующем JS и коллизии неизменяемых файлов.
При ошибке активная копия сохраняется. Архивы ограничены 256 MiB в сжатом
и 512 MiB в распакованном виде; допускаются только обычные файлы и каталоги.

## Обновление и откат

После настройки секрета отправьте изменения в main.
Actions выполнит npm ci, сборку, тесты публикации и загрузит архив по SSH.
Nginx и игровые процессы при публикации не перезапускаются.

Для отката оператор сервера выбирает прежний каталог из `site/releases`
и атомарно заменяет ссылку `site/current`. Не удаляйте старую активную копию
до проверки новой. Очистка старых выпусков пока выполняется вручную.

## Сертификаты и DNS

ACME webroot находится отдельно: `/var/www/qupersimulator/acme`.
HTTP-путь `/.well-known/acme-challenge/` должен оставаться доступным для
автоматического продления сертификатов. После первичного DNS-подтверждения
основного домена Certbot переводится на webroot через `certbot reconfigure`;
результат проверяется до завершения переноса.

`api.qupersimulator.ru` имеет собственный виртуальный хост и сертификат.
Его конфигурация, игровые службы и firewall не входят в публикацию сайта.
