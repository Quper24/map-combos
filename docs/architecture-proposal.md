# Предлагаемая архитектура

Статус: основа реализована локально 2 ноября 2026 года; размещение на Linux впереди.
Согласованные продуктовые требования находятся в redesign-plan.md.

## Основа

Сохранены React и Vite. Реализованы строгий JSON для редактируемого контента,
CSS Modules для локальных стилей, загрузка страниц по требованию и проверка
контента перед сборкой. Код пока на JavaScript/JSX; TypeScript остаётся
предложением для следующего технического этапа.
Для первой версии достаточно статического сайта без базы данных.

Структура должна помогать находить страницу, её поведение и стили рядом,
не создавая отдельные слои ради каждого небольшого компонента.

```text
content/
  combos/               # Сборки по версиям игры, включая все старые
  mods/                 # Собственные моды и плагины
  videos.json           # Видео и ссылки на площадки
  vtc.json              # Компания, серверы, ссылки на сборки
  site.json             # Общие сведения и социальные ссылки
src/
  app/                  # Запуск приложения, маршруты, общий каркас
  pages/                # Главная, сборки, сборка, VTC, моды, мод, видео
  features/             # Фильтрация каталога и другие самостоятельные функции
  components/           # Повторно используемые элементы интерфейса
  lib/                  # Чтение данных, даты, URL и небольшие общие функции
  styles/               # Цвета, размеры, типографика, базовые стили
public/
  img/                  # Существующие изображения сохраняются
  profiles/             # Существующие файлы профилей сохраняются
scripts/                # Миграция и проверка контента
docs/                   # План, правила обновления и размещения
deploy/                 # Конфигурация размещения после изучения сервера
```

CSS страницы или компонента хранить рядом в файле *.module.css.
Общие переменные цвета, отступов, скруглений и анимаций определить один раз.
Пути существующих изображений не менять без необходимости.

## Контент и сохранность

- Сначала подготовить обратимую миграцию и проверку сохранности 50 записей.
- Не смешивать авторские разработки с существующими сборками модов:
  текущие модпаки тоже сохранить как существующие материалы.
- Сохранить все поля, ссылки, инструкции, профили и работу автоматической
  расстановки модов; не удалять поля, смысл которых ещё не изучен.
- Проверять уникальность id, структуру записей, локальные файлы и связи
  материалов. Невалидные данные должны обнаруживаться до публикации.
- Проверку внешних URL отделить от локальной сборки: временный отказ
  стороннего сайта не должен автоматически удалять материал.
- Добавить понятную инструкцию: как обновить сборку, добавить мод или видео.
- Актуальную версию игры задавать единообразно. Сейчас в versions.js
  одновременно отмечены current/default у 1.60 и 1.61; при рефакторинге
  устранить неоднозначность без удаления записей этих версий.

## Производительность и оформление

- Загружать код разделов по мере открытия, не включать все архивные данные
  и тяжёлые компоненты в начальную загрузку без необходимости.
- Превью делать подходящего размера; полные изображения порядка карт
  сохранять читаемыми. Задавать размеры изображений, чтобы избежать сдвигов.
- Картинки ниже первого экрана загружать отложенно; главный видимый кадр
  не задерживать отложенной загрузкой.
- Видеоплееры загружать по действию пользователя. В каталоге видео
  достаточно локального превью и ссылок на площадки.
- Предпочитать короткие CSS-переходы прозрачности и transform:
  наведение, фокус, открытие меню. Избегать постоянного движения,
  тяжёлых фоновых эффектов и задержек перед доступом к содержимому.
- Учитывать prefers-reduced-motion и сенсорное управление. Кнопки выбора
  площадки на превью должны быть доступны без наведения мыши.
- Проверять скорость на производственной сборке и мобильном размере.
  Числовые бюджеты определить после исходного замера; не обещать оценки
  производительности до измерений.

## Размещение

- Linux, существующий домен qupersimulator.ru, адреса без #.
- До настройки изучить службы, занятые порты и текущее размещение;
  выбрать конфигурацию, совместимую с игровыми серверами.
- Не изменять службы игр и правила сети без установленной необходимости.
- Подготовить конфигурацию веб-сервера, HTTPS, обработку внутренних
  маршрутов и переход старых hash-ссылок на новые страницы.
- Сначала проверить новую версию отдельно, затем переключать основной сайт.
- Сохранить предыдущий выпуск для отката; способ доставки файлов
  и автоматизации определить после изучения сервера.
- Если нужна остановка игр или перезагрузка, согласовать время с владельцем.

## Проверка результата

- Сверка всех исходных данных после миграции.
- Фильтры, архив версий, страницы сборок и разработок, необязательные поля.
- Профили, автоматическая расстановка, инструкции и изображения порядка карт.
- Старые ссылки, прямой вход на страницы и обновление браузера без 404.
- Мобильная навигация, клавиатура, видимый фокус и режим уменьшения движения.
- Отсутствие ошибок сборки и проверка размера загружаемых ресурсов.

Миграцию данных, структуру кода, визуальные изменения и перенос сервера
выполнять отдельными проверяемыми этапами.
